# Обновление Keenetic с автономным откатом

Задачи: XKEEN-2, MIHOMO-4, ZASH-2. Скрипт рассчитан на существующую ARM64-установку:
`/opt/sbin/mihomo`, `/opt/sbin/xkeen`, `/opt/sbin/.xkeen`, `/opt/etc/init.d/S05xkeen`,
`/opt/etc/mihomo/config.yaml` (в том числе symlink), панель `zash`, mixed port 1080 и API 9090 без secret.
Нужны Python 3.12+, gh, OpenSSH на компьютере; curl, jq, yq, tar, sha256sum на роутере.
Пароли не сохраняются: используется настроенный SSH-host `keenetic`.

Подготовить и проверить содержимое, не меняя устройство:

```powershell
python tools/keenetic-release/deploy.py --adaptive
```

Развернуть последние опубликованные релизы трёх форков:

```powershell
python tools/keenetic-release/deploy.py --adaptive --apply
```

Без `--adaptive` меняется только адрес обновления панели; остальные параметры YAML сохраняются.
С `--adaptive` включаются GET-проверки ROUTER каждые 300 секунд, 4 одновременно,
два подтверждения сетевого режима и fallback в EU/RU/Без белых списков/AUTO.
DNS, правила, параметры подключений, фильтры групп и остальные selectors проверяются на неизменность.
Проверки зависят от ответа выбранных сайтов, поэтому режим белых списков остаётся предположением.

Перед остановкой проверяются SHA-256 архивов и конфиг новым ядром. Короткая остановка
нужна для согласованного снимка cache.db и встроенного Tailscale. Снимок включает
Mihomo, XKeen, службу, панель, всю текущую конфигурацию/профили/провайдеры/состояние
Mihomo (кроме накопленной папки backup), настройки XKeen и его NDM hooks.
Новая служба сохраняет значения прежних параметров через тот же перечень, что штатный updater.

При ошибке активации автоматически запускается rollback. Отдельный watchdog также
откатывает через 10 минут, если компьютер не подтвердил успешную проверку API/UI,
ранее работавшего проксируемого GET и скачивание проверенной копии резервного архива.
Загрузка не зависит от открытого браузера или продолжения SSH-сеанса.

## Ручной откат

Конкретный путь выводится в конце deploy. На компьютере создаётся готовый `rollback.ps1`
в `%LOCALAPPDATA%/HomeNet/deployments/<timestamp>/`; рядом лежат `report.json`, `before.tar`
и SHA-256. Каталог имеет закрытый ACL и содержит конфигурацию с секретами: не коммитить.

Универсальный скрипт этого репозитория:

```powershell
./tools/keenetic-release/rollback.ps1 -Backup /opt/backups/homenet-YYYYMMDD_HHMMSS -Check
./tools/keenetic-release/rollback.ps1 -Backup /opt/backups/homenet-YYYYMMDD_HHMMSS
```

Или непосредственно на роутере (в том числе из локальной консоли):

```sh
sh /opt/backups/homenet-YYYYMMDD_HHMMSS/rollback.sh --apply
```

Откат не требует исправного нового ядра: проверяет SHA-256, останавливает новую службу,
при необходимости использует старую, восстанавливает файлы и запускает прежнюю версию.
Symlink конфига сохраняется. Новые деревья панели/модулей перемещаются в резервный каталог,
чтобы их файлы не смешались со старыми. Архив не удаляется. Состояние и ручные изменения,
сделанные после развёртывания, при откате возвращаются к снимку.

`test_transaction.py` проверяет ручной откат, отказ новой службы и срабатывание watchdog
на временном дереве `/opt`, без настоящих сетевых служб.
